# 笔记管理工作台设计

## 背景与目标

Marginalia 当前的 `#/creation` 页面同时承担素材筛选、感悟编辑和稿件生成，笔记管理能力较弱，且只能可靠展示已进入当前设备 IndexedDB 的记录。本次改造将该页面明确为“笔记管理”工作台，提供全书库查询、编辑、批量标签、回收站和 Markdown 下载。

本设计的目标是：

- 在线时完整管理服务器中的所有划线与感悟；
- 离线时仍可管理当前设备已经缓存的内容；
- 清楚区分“删除感悟”“移入回收站”和“永久删除”；
- 保留本地优先编辑和持久同步队列；
- 不破坏现有书库、阅读器、历史稿件接口及历史数据；
- 保持 `#/creation` 路由和浏览器历史兼容。

## 范围

### 本期实现

- 笔记全文搜索；
- 按书籍、标签、内容类型、高亮颜色、同步状态筛选；
- 按最近修改、最近创建、阅读位置、书名排序；
- 服务端分页和聚合选项；
- 笔记详情编辑：感悟、标签、高亮颜色；
- 删除感悟但保留划线；
- 单条和批量标签添加、移除；
- 单条和批量移入回收站、恢复、永久删除；
- 下载当前筛选结果的 Markdown；
- 在线全量数据和离线 IndexedDB 回退；
- 桌面与移动端适配；
- 修正阅读侧栏中过时的单击／双击提示。

### 不在本期范围

- 独立于划线的自由笔记；
- 修改划线原文、书名、作者、章节、CFI、阅读进度或创建时间；
- JSON 下载、Obsidian 导出或其他导出格式；
- 公众号／视频号稿件生成、稿件编辑和稿件导出入口；
- 自动清空回收站；
- 回收站之外的通用版本历史；
- 删除历史稿件接口、数据库表或已有稿件数据；
- 更改 `/book-chat/` 的阅读体验。

历史稿件能力仅从前端入口移除。后端接口、数据表、历史数据和兼容代码继续保留。

## 总体架构

采用专用笔记管理 API、现有本地同步队列和 IndexedDB 离线回退相结合的方案。

### 数据权威与读取路径

- 在线管理页以服务器 SQLite 为全书库查询来源。
- 页面通过 `GET /api/notes` 执行搜索、筛选、排序和分页。
- IndexedDB 继续作为阅读器即时编辑、本地缓存和离线管理的数据来源。
- 请求失败或浏览器离线时，页面切换到 IndexedDB 查询，并显示“离线数据，可能不完整”。
- 本地待同步记录按稳定身份覆盖同一条服务器记录，保证刚完成的本地编辑不会被旧服务器值闪回。
- 本地待移入回收站或待永久删除的记录不出现在正常列表。
- 后台刷新不得覆盖详情面板中尚未保存的草稿。

稳定身份优先使用服务器 `id`；尚未获得服务器 ID 的记录使用 `client_id`。API 响应同时返回两者，以便合并在线数据和本地待同步数据。

### 写入路径

- 单条编辑先写 IndexedDB，再进入现有持久 `sync_queue`。
- 在线批量操作调用专用批量 API，并附带 `operation_id` 保证幂等；成功后更新本机已缓存的对应记录。
- 离线批量操作拆分为逐记录同步队列操作，联网后重放。
- 本机没有缓存 EPUB 的服务器笔记不要求下载 EPUB；只更新已有的笔记缓存。
- 操作失败时不提前从 UI 移除数据，编辑草稿保持可恢复状态。

### 数据模型

为 `highlights` 增加可空字段：

```text
deleted_at TEXT NULL
```

- `deleted_at IS NULL`：正常记录；
- `deleted_at IS NOT NULL`：回收站记录。

初始化数据库时通过现有 schema 升级方式增列和建索引，不引入 Alembic。至少为活动／回收站查询和更新时间排序建立适用索引。FTS 索引继续覆盖书名、作者、章节、划线、感悟与标签，但正常搜索默认排除回收站。

IndexedDB 数据库升级一个版本，在 `highlights` 记录中允许保存 `deleted_at`。现有记录缺少该字段时视为 `null`，不做破坏性迁移。原有 `deleted_highlights` 仓库不主动删除，避免破坏旧数据；新回收站流程不依赖它。

## 同步语义

现有同步操作扩展为：

- `highlight.upsert`：创建或更新正常笔记，也可同步感悟、标签和颜色；
- `highlight.trash`：设置 `deleted_at`；
- `highlight.restore`：清除 `deleted_at`；
- `highlight.delete`：永久删除回收站中的记录。

规则：

- 新客户端只允许对已经位于回收站的记录执行永久删除；
- 为兼容旧客户端，缺少新协议版本标识的历史 `highlight.delete` 请求继续按旧语义永久删除；
- 新客户端的同步请求携带协议版本，使服务器能够区分旧删除和新永久删除；
- `trash`、`restore` 和 `delete` 均通过现有 `op_id` 去重；
- 重复移入回收站、重复恢复以及重复永久删除均为幂等操作；
- 服务器同步快照包含活动记录和回收站记录的必要状态，使其他设备能够删除本地活动副本或恢复记录；
- 永久删除成功后，服务器快照中不再返回该记录；客户端根据确认后的操作清理本地记录。

书籍整本删除仍按现有行为删除关联数据，不经过笔记回收站；其确认文案继续明确说明影响范围。

## 页面结构与交互

路由继续使用 `#/creation`，页面标题、导航名称和可访问标签统一改为“笔记管理”。主界面、阅读页和笔记管理页仍是同级工作页，笔记管理通过“返回主界面”退出。

### 顶部工具区

包含：

- 全文搜索框；
- “导出 Markdown”按钮；
- 正常列表／回收站切换；
- 在线、离线、加载中和错误状态；
- 失败后的“重试”操作。

全文搜索覆盖：

- 书名；
- 作者；
- 章节；
- 划线原文；
- 感悟；
- 标签。

查询去除首尾空白。少于 2 个字符时不发起全文搜索，并显示简短提示；输入采用防抖，避免每次按键立即请求。

### 筛选与排序区

支持：

- 书籍：单选；
- 标签：多选，匹配规则为同时包含所有所选标签；
- 内容类型：全部、有感悟、仅划线；
- 高亮颜色：全部、黄、绿、蓝、粉；
- 本机同步状态提示：全部、已同步、待同步；
- 排序：最近修改、最近创建、阅读位置、书名；
- 清空筛选。

服务器笔记没有客户端待同步概念，因此同步状态不能作为全书库服务端筛选条件。“待同步”视图专门列出本机 IndexedDB 与同步队列中的待提交记录，不与服务端分页混合；“已同步”不作为独立全书库筛选，只用于记录状态展示。离线模式下所有筛选和排序在 IndexedDB 结果上执行，并明确说明范围仅限本机缓存。

筛选变化时回到第一页并清空跨页选择，避免用户误以为隐藏记录仍处于选中状态。

### 列表和详情

桌面端采用列表与详情双栏；移动端列表项打开全屏详情。

列表卡显示：

- 复选框；
- 书名与章节；
- 划线摘要；
- 感悟摘要；
- 标签；
- 高亮颜色；
- 更新时间；
- 同步状态。

详情面板中：

- 可编辑：感悟、标签、高亮颜色；
- 只读：划线原文、书名、作者、章节、阅读位置、创建时间；
- 操作：保存、删除感悟、移入回收站。

标签输入支持中文逗号和英文逗号，保存时去除空白、空标签和重复标签，保留首次出现顺序。

用户切换笔记、关闭移动详情、返回主界面、切换回收站或浏览器返回时，如果详情存在未保存修改，必须提示“保存并继续／放弃修改／取消”。后台刷新和同步状态变化不得关闭详情或覆盖草稿。

“删除感悟”只清空 `note` 并将状态更新为无感悟状态，保留划线、标签、颜色和定位。成功后显示短暂撤销条；撤销恢复删除前的感悟并重新进入同步流程。

### 批量操作

正常列表支持：

- 全选当前页；
- 添加标签；
- 移除标签；
- 移入回收站。

批量操作只作用于用户明确勾选的记录，不隐式作用于筛选结果中的所有记录。“全选”只选择当前页，并在按钮或提示中明确当前页数量。

添加标签为追加并去重，不覆盖原标签。移除标签只删除明确指定的标签。批量标签对整批记录采用事务语义：全部成功或全部失败。

移入回收站前显示选中数量并确认。成功后从正常列表移除，并显示可撤销提示；撤销等价于批量恢复。

### 回收站

回收站复用搜索、书籍筛选、分页和列表组件，但不提供内容编辑和 Markdown 导出。支持：

- 单条或批量恢复；
- 单条或批量永久删除；
- 清空回收站。

永久删除和清空回收站必须显示记录数量并二次确认。回收站不自动过期或清理。失败的永久删除继续保留在列表中。

### 阅读侧栏文案

移除“单击跳回原文，双击编辑感悟”这一与实际实现不符的说明，改为说明展开记录后可使用“定位原文”和“编辑感悟”按钮。现有按钮行为不改变。

## API 设计

### 查询笔记

```http
GET /api/notes
```

查询参数：

- `q`：全文搜索，非空时至少 2 个字符；
- `book_id`：精确书籍 ID；
- `tag`：可重复参数，多个标签按 AND 语义；
- `note_kind=all|reflected|highlight_only`；
- `color=yellow|green|blue|pink`；
- `view=active|trash`；
- `sort=updated_desc|created_desc|position|book`；
- `limit`：有上限的页大小；
- `offset`：分页偏移。

`sync_state` 不作为服务端过滤参数，因为该状态属于设备本地同步队列，不是服务器记录属性。前端将“待同步”实现为独立的本机队列视图，不对已经分页的服务器结果做二次过滤。

响应结构：

```json
{
  "items": [],
  "total": 0,
  "limit": 50,
  "offset": 0,
  "has_more": false,
  "facets": {
    "books": [],
    "tags": []
  }
}
```

`items` 返回完整管理字段，包括 `id`、`client_id`、`book_id`、书籍与定位信息、内容字段、颜色、状态、时间和 `deleted_at`。`facets` 基于当前视图和搜索条件生成，但不受同类 facet 自身选择限制，以便用户继续调整筛选。

全文搜索复用现有 FTS5 trigram 与 `LIKE` 回退：可用时对至少 3 字符的查询使用 FTS；2 字符查询或无 trigram 支持时使用参数化 `LIKE`。所有 SQL 筛选均使用参数，不拼接用户输入。

### 单条编辑

管理页沿用现有本地 `highlight.upsert` 同步路径，不新增并行的单条写接口。服务端原有 `PATCH /api/highlights/{id}` 为兼容保留，但不是新页面的首选写路径。

### 批量标签

```http
POST /api/notes/batch/tags
```

请求包含：

- `operation_id`；
- `ids`；
- `action=add|remove`；
- `tags`。

单次 ID 数量设固定上限。服务器在一个事务中处理，返回受影响数量和变更后的记录摘要。重复 `operation_id` 返回首次执行结果，不重复应用。

### 批量回收站操作

```http
POST /api/notes/batch/trash
POST /api/notes/batch/restore
POST /api/notes/batch/delete
```

请求包含 `operation_id` 和 `ids`。永久删除仅接受当前处于回收站的记录；不存在或已经永久删除的 ID 按幂等成功处理，但响应区分实际变更数量与已处于目标状态数量。

清空回收站通过批量永久删除接口执行，前端先分页取得当前回收站 ID；服务端仍强制单次上限。若记录超过单次上限，前端分批提交并显示进度。任一批失败即停止，已成功批次不回滚，界面重新查询以显示真实剩余数据。

### Markdown 下载

```http
GET /api/notes/export.md
```

接受与活动列表相同的 `q`、`book_id`、重复 `tag`、`note_kind`、`color` 参数。导出不接受 `view=trash`，不包含回收站记录，也不接受设备本地 `sync_state` 筛选。若当前界面启用了“待同步”筛选，导出按钮禁用并提示先完成同步，因为服务器无法导出尚未上传的本地状态。

导出范围是符合当前服务器筛选条件的全部记录，不受当前分页和勾选状态影响。输出按书名分组，每本书内按阅读位置排序。每条包含：

- 书名；
- 作者；
- 章节；
- 阅读进度；
- 划线；
- 感悟（如有）；
- 标签（如有）；
- 创建时间和更新时间。

无结果时返回 422 和明确中文错误。响应使用 Markdown MIME 类型和下载头，文件名为 `Marginalia-笔记-YYYY-MM-DD.md`。文件在响应中生成，不写入 Obsidian 仓库或持久导出目录。

离线时 Markdown 导出由浏览器根据当前离线筛选结果生成，以保证离线仍可下载；文件显著标注“离线导出，可能不完整”。在线模式始终使用服务端导出，以保证列表条件和完整数据一致。

## 错误处理与一致性

- 初次在线查询失败且本地有数据：显示错误和重试按钮，同时允许进入离线结果；
- 查询失败且本地无数据：显示空错误态，不伪装成“没有笔记”；
- 后续刷新失败：保留已有列表，不清空屏幕；
- 单条保存失败：保留编辑内容和脏状态，允许重试；
- 批量操作失败：不提前移除或修改列表；
- 永久删除失败：记录留在回收站；
- 本地存储失败：明确提示该修改未获得离线保护，不显示成功；
- 网络恢复：提示可重新加载全书库数据，不在存在未保存草稿时自动替换详情；
- 空筛选结果与请求错误使用不同视觉状态；
- 所有删除、恢复和批量标签请求可安全重试。

## 可访问性与响应式要求

- 所有筛选、菜单、复选框和按钮具备关联标签与键盘焦点状态；
- 批量操作结果和错误通过可访问状态区域播报；
- 颜色不能作为唯一状态提示，卡片同时显示颜色名称；
- 对话框锁定焦点并支持 Escape 关闭，存在未保存内容时 Escape 同样触发保护；
- 桌面端保持双栏，窄屏切换为列表与全屏详情，不产生横向溢出；
- 继续遵循暖纸色、墨松绿、小圆角和中文优先排版。

## 兼容性与数据保护

- `#/creation` 路由不变；
- 现有 `/api/highlights`、`/api/materials`、`GET /api/notes/export` 和 Obsidian 接口继续保留；
- 历史稿件接口、表、索引和数据不删除；
- `deleted_highlights` IndexedDB 仓库不删除；
- 数据库升级只增列、增索引，不重建或清空用户表；
- 旧客户端仍能读取和同步正常记录；
- `/book-chat/` 共享书库和进度 API 的行为不得改变；
- Service Worker 继续对应用壳网络优先、EPUB 使用独立稳定缓存；发布时更新应用壳版本，不清除 EPUB 缓存。

## 完成标准

满足以下条件才视为完成：

- 在线时可查询和管理服务器全书库笔记；
- 离线时可管理本机缓存并明确提示数据范围；
- 搜索、筛选、排序、分页与 Markdown 导出语义一致；
- 感悟、标签和颜色可安全编辑，未保存草稿不会被导航或刷新静默丢弃；
- 删除感悟、移入回收站和永久删除在文案与数据行为上严格区分；
- 单条和批量回收站操作跨设备一致且可重试；
- 只有 Markdown 下载作为新笔记管理页的导出能力；
- 稿件生成相关前端入口已移除，但历史接口和数据仍完整保留；
- `#/creation` 和页面历史保持兼容；
- 后端与前端全套测试通过，隔离数据的真实同源验收通过。
